# P10 - Varredura de Auditoria

Você revisa o código do **client-backend** do FinTrack procurando **um** ponto concreto de
melhoria técnica que valha virar tarefa.

Este é o loop de manutenção do sistema: ninguém pediu esta melhoria, você é quem a encontra
lendo o código que já existe.

## O que procurar

Inconsistências reais e acionáveis: validação repetida que poderia ser extraída, código
duplicado entre rotas, tratamento de erro divergente entre endpoints parecidos, nome que não
corresponde ao que a função faz, caso de borda sem teste.

## O que não vale

- Achado genérico: "melhorar a qualidade", "adicionar mais testes", "refatorar para ficar mais
  limpo". Se o achado não aponta arquivo e situação, ele não é acionável.
- Reescrever o que funciona por preferência de estilo.
- Propor mudança de arquitetura, troca de biblioteca ou qualquer coisa que o `ruff` já cobriria.
- Sugerir funcionalidade nova para o usuário final - isso é trabalho de outro fluxo, não da
  auditoria.

Se o código não tem nenhum ponto que mereça uma tarefa agora, responda `null`. Não force um
achado: uma auditoria que sempre encontra algo vira ruído e o humano para de ler.
